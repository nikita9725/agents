# Тестирование

| Уровень | Что проверяет | Зависимости |
|---|---|---|
| unit | API, модели, DBOS enqueue/status, политики графа, ошибки и логи | Подмены разрешены только здесь |
| integration | Реальная задача, LLM, сохранение результата и checkpoints | FastAPI с DBOS, PostgreSQL, LLM |
| e2e | SSE, отмена, очередь, перезапуск приложения, SIGKILL | Полный настоящий стек |

```sh
make unit-test
make integration-test
make e2e-test
make test
make test TEST_PATH=tests/unit/test_planner.py
make lint
make pre-commit
```

Для полного набора нужны работающий Docker и настоящие LLM-настройки в .env.
Ключ LangSmith не нужен. Отсутствие LLM-настроек считается ошибкой, не skip.
Pytest запускается на хосте; стек запускается через make up, а управление контейнерами для аварийных сценариев
находится в tests/stack.py.
Тесты используют отдельный проект etl-agent-test, volume task_data и порт
AGENT_TEST_PORT (18123); PostgreSQL публикуется на POSTGRES_TEST_PORT (15432). После проверки контейнеры останавливаются, данные сохраняются.
Не запускайте integration/e2e одновременно. Рабочий проект не используется.

Обычные задачи создаются через POST /tasks. Для сценария очереди служебная
Python-помощник из Docker-сети добавляет реальные DBOS workflows с задержкой 30 секунд.
Отмена и чтение выполняются публичным API; тестовых полей в API нет.

Аварийный тест наблюдает running и сохранённый input checkpoint, убеждается,
что planning ещё не завершился, и отправляет SIGKILL общему процессу приложения под Docker init.
Проверяются Docker exitCode=137, увеличение RestartCount и завершение того же
workflow/task_id без resubmit или ручного resume. Если задача успела завершиться
до аварии, тест падает как непроверенный. Готовность проверяется через публичный /ready. Для проверки неверного LLM-ключа пересоздаётся тестовый
контейнер приложения с временным окружением; .env не меняется, настройки восстанавливаются.
