# Предложение шага диагностики

Пользователь описывает проблему, например: «Вчера не загрузились продажи:
входной файл sales.csv отсутствует». Планировщик предлагает одно конкретное действие
и кратко объясняет, почему его стоит выполнить. Примеры входных задач:
[examples/goals.json](../examples/goals.json).

## Контракт модели

Порт `Planner.propose(goal)` возвращает `NextAction` с непустыми полями:

- `action` — следующее действие;
- `rationale` — краткое обоснование на основе входных данных.

Адаптер `OpenAIPlanner` использует LangChain `ChatOpenAI` и Pydantic-схему
через `with_structured_output(method="function_calling", strict=True)`.
Провайдер должен поддерживать этот контракт; неподдерживаемый ответ приводит к ошибке.
В финализации второй запрос к модели не выполняется.

## Настройки

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` | Базовый URL OpenAI-совместимого API |
| `LLM_MODEL` | Идентификатор модели у выбранного провайдера |
| `LLM_API_KEY` | Ключ доступа; хранится в окружении или локальном `.env` |
| `LLM_EXTRA_BODY` | JSON-объект дополнительных параметров провайдера; по умолчанию `{}` |

Для DeepSeek с принудительным вызовом `NextAction` отключите thinking:

```dotenv
LLM_EXTRA_BODY={"thinking":{"type":"disabled"}}
```

У `deepseek-flash` thinking включён по умолчанию. В этом режиме DeepSeek
отклоняет принудительный `tool_choice` с HTTP 400.
[Ограничение описано в документации DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/).
Дополнительные параметры передаются явно в `ChatOpenAI.extra_body`;
автоматического определения провайдера и смены режима нет.
Для других провайдеров оставьте `{}` либо задайте поддерживаемые ими параметры.
Некорректный JSON или значение, отличное от объекта, завершают запуск с ошибкой.

При запуске через Compose переменные передаются контейнеру явно. `.env` не попадает
в Docker-образ. Таймаут SDK и одной попытки узла — 30 секунд.
SDK-повторы отключены; временные ошибки повторяет RetryPolicy графа, максимум
три попытки. Итоговый статус доступен в GET /tasks/{task_id}. Постоянные
ошибки и неверная структура ответа не повторяются.

## Границы поведения

Prompt задаёт роль помощника по ETL и требует отвечать на языке пользователя.
Агент не имеет инструментов: он не читал логи, не проверял статусы и не менял систему.
Он не должен придумывать результаты проверок или утверждать, что сбой устранён.
Если сведений мало, действие должно предлагать получить конкретные недостающие данные.
Обоснование — короткое объяснение действия, а не внутренние рассуждения модели.

Только в unit-тестах используется отдельный fake-планировщик. Выбрать его через HTTP или
настройки рабочего приложения нельзя.
