# Тестирование

| Уровень | Что проверяет | Зависимости |
|---|---|---|
| unit | API, модели, DBOS enqueue/status, политики графа, ошибки и логи | Явно внедрённые типизированные fakes и HTTP-транспорт |
| integration | Реальный выбор трёх tools, observations, LLM и checkpoints | FastAPI с DBOS, PostgreSQL, LLM |
| e2e | SSE, отмена, очередь, перезапуск приложения, SIGKILL | Полный настоящий стек |

```sh
make unit-test
make integration-test
make e2e-test
make test
make test TEST_PATH=tests/unit/test_planner.py
make lint
make pre-commit
```

Pytest использует `--import-mode=importlib` из `pyproject.toml`, чтобы одноимённые
файлы разных наборов (например, unit/test_tools.py и integration/test_tools.py)
не конфликтовали при полном запуске `make test`.

Для полного набора нужны работающий Docker и настоящие LLM-настройки в .env.
Ключ LangSmith не нужен. Отсутствие LLM-настроек считается ошибкой, не skip.
Pytest запускается на хосте; стек запускается через make up, а управление контейнерами для аварийных сценариев
находится в tests/stack.py.
Тесты используют отдельный проект etl-agent-test, volume task_data и порт
AGENT_TEST_PORT (18123); PostgreSQL публикуется на POSTGRES_TEST_PORT (15432). После проверки контейнеры останавливаются, данные сохраняются.
Не запускайте integration/e2e одновременно. Рабочий проект не используется.

Обычные задачи создаются через POST /tasks. Для сценария очереди служебная
Python-помощник из Docker-сети добавляет реальные DBOS workflows с задержкой 30 секунд.
Отмена и чтение выполняются публичным API; тестовых полей в API нет.

Аварийный тест наблюдает running и сохранённый input checkpoint, убеждается,
что planning ещё не завершился, и отправляет SIGKILL общему процессу приложения под Docker init.
Проверяются Docker exitCode=137, увеличение RestartCount и завершение того же
workflow/task_id без resubmit или ручного resume. Если задача успела завершиться
до аварии, тест падает как непроверенный. Готовность проверяется через публичный /ready. Для проверки неверного LLM-ключа пересоздаётся тестовый
контейнер приложения с временным окружением; .env не меняется, настройки восстанавливаются.

Unit-тесты инструментов проверяют схемы, арифметику, ограничения чтения и поиска,
ошибки путей и UTF-8. Сценарные модели проверяют возврат observations, исправление
аргументов, бюджет и восстановление после planning, acting, tools и observation. MockTransport проверяет
реальный формат запросов LangChain без сети. Интеграционные тесты вызывают каждый
инструмент через настоящую LLM и проверяют использование результата в ответе.


## Явные зависимости

Все unit-тесты используют зависимости, переданные через конструкторы или параметры:
типизированные fakes портов, фабрику runtime и `httpx.MockTransport` для протокола LLM.
Глобальные подмены через monkeypatch, unittest.mock, замену атрибутов модулей или
изменение os.environ запрещены. Трассировка unit-тестов отключается штатным
`langsmith.tracing_context(enabled=False)`.

Чтение настроек окружения проверяется отдельными subprocess с явно собранным env
и временным рабочим каталогом. E2E неверного ключа передаёт ключ окружению
дочернего процесса Docker Compose, затем в finally восстанавливает контейнер
с исходной конфигурацией. Родительское окружение и .env не меняются.

`test_full_graph_reads_searches_and_calculates` проходит полный граф через публичный
API: чтение etl.log, поиск ошибки даты, расчёт 25% и финализация. Проверяются
типизированные observations, связь tool_call_id, чтение до расчёта и числовой процент
в ответе. Проверяются однократное планирование, повторные acting/observation и SSE sequence.
Полный текст, формула и точное число шагов не фиксируются; дополнительные
вызовы и исправленные ошибки допустимы. Повторы упавших E2E не используются.

Аварийный E2E подписывается на Docker die до отправки SIGKILL и ждёт событие
с ограничением времени. Проверка не зависит от короткого окна чтения событий
после аварии или переполнения истории Docker events.

## День 4

Сценарные unit-тесты проверяют использование notes после удаления старого обмена
из контекста, завершение по критериям, лимиты выжимки и некорректные evidence.
Проверяются повторные вызовы (успех и ошибка), дедупликация внутри пакета,
канонические аргументы, остановка без новых данных, retry observation без повторного
выполнения tools, восстановление памяти после tools/observation и delta каждого
узла. Тест HTTP-транспорта проверяет отдельный structured вызов WorkingMemory.
Клиент проверяется на вывод delta и дедупликацию SSE replay.
